# W07 업무 명세

## 목표와 처리 단위

월 정산 요청을 받으면 영업지원이 관련 대리점의 합산 근거를 확인하고, 권한자가 그룹 단위로 승인하며, 회계·자금이 각 대리점에 지급한 결과를 대사한다. 등록정보가 바뀌면 기존 결재의 영향 범위를 찾아 미집행 건의 지급 계획까지 갱신한다. 결재자는 무엇이 한도에 포함됐는지, 회계 담당자는 어떤 승인 명세로 얼마를 지급할 수 있는지 같은 정산건에서 추적할 수 있어야 한다.

## 사용자 역할과 실행 권한

| 역할 | 실행할 수 있는 작업 |
|---|---|
| 영업지원 담당자·전결권자 | 정산월 접수, 동일 ID 금액 불일치의 확정액·판단 근거 기록, 관계 근거 검토, 대리점 소명 요청·회신 등록, 증빙 확인·등록정보 정정, 결재 상신. 팀 전결권이 있는 사용자만 전결 범위 안에서 승인·반려·보완 요청을 할 수 있다. |
| 영업임원 | 상신된 한도 초과 결재안과 근거를 열람하고 승인·반려·보완 요청을 결정한다. |
| 회계·자금 | 승인 명세·수취계좌·자금을 확인하고 지급지시 전송과 모의 대사를 수행한다. 회신이 상충하면 모든 시도의 증빙을 확인해 지급 완료 또는 미지급을 기록한다. 재시도와 기지급 건 사후 검토도 담당한다. |
| 대리점 | 자기 소명건의 공유 사유·증빙을 제공한다. 로컬 시연에서는 영업지원이 회신 주체와 수신일을 기록한다. |

로컬 시연은 역할이 부여된 시연 사용자로 동작한다. 처리 권한은 서버에서 확인하며 결정자·시각을 기록한다. AI는 조회된 근거로 관계 요약, 소명 질문, 결재 사유 초안을 작성한다. 정산 합계·승인권자를 계산하는 규칙, 사람의 결재, 지급 도구의 실행 권한은 [설계](design.md)를 따른다.

## 업무 화면 4개

| 화면·주 사용자 | 입력 | 처리 | 결과와 다음 작업 |
|---|---|---|---|
| ① 월 정산 접수 · 영업지원 | 정산월, 대리점 마스터·장려금 지급표·회수 이력 | 적격 여부와 원본 ID를 확인한다. 같은 ID·내용은 기존 건을 열고, 새 ID는 해당 월 심사에 추가해 누계를 재계산한다. 같은 ID의 금액이 달라지면 확인 작업을 연다. | 대리점별 금액, 그룹 월 합계, 예상 승인권자, 확인 필요 건이 있는 월별 목록. 정산건을 선택하면 근거 화면으로 이동한다. |
| ② 관련자·소명 · 영업지원 | 정산건, 대리점별 등록정보, 회수계좌, 대리점 회신·증빙 또는 정정 요청 | 직접 일치한 키와 간접 연결 경로를 표시한다. AI가 차이와 확인할 사항을 요약한다. 담당자가 소명 기한·담당자를 지정하고 회신·검토 결과를 기록한다. 정정 시 적용일과 근거를 입력한다. | 소명 대기·회신 검토·해소 상태, 변경 전후 그룹 및 영향받는 결재·지급 목록. 상신 또는 보완 작업으로 이어진다. |
| ③ 그룹 결재 · 영업지원·영업임원 | 정산월, 그룹 구성 버전, 월 누계 명세, 이번 승인 요청 금액, 소명 결과 | 상신·결정 직전 누계를 재계산하고 해당 권한자에게만 결정 동작을 허용한다. 결재자는 승인·반려·보완 요청과 사유를 기록한다. | 결재 버전과 결정 이력. 승인된 신규 명세마다 지급 준비 건을 생성한다. 보완 요청은 소명 담당자에게 돌아간다. |
| ④ 지급지시·대사 · 회계·자금 | 승인 명세, 증빙으로 확인한 대리점별 수취계좌, 지급지시 ID와 모의 은행 회신 | 승인 버전·금액·계좌 확인 후 전송하고, 은행 회신과 지시의 대상·금액을 대조한다. 지급 전 정정, 결과 미확인, 실패를 각각 구분한다. | 지급 완료·실패·보류 건과 사유, 다음 확인 작업. 정산건에서 결재자·지시·은행 회신을 역추적할 수 있다. |

## 사용 설명

공통 메뉴의 **사용 설명**은 현재 담당자의 업무 절차를 먼저 보여준다. 역할별로 시작할 화면, 대조할 근거, 완료 상태와 인계 대상을 안내한다. 설명 안에서 다른 역할을 골라도 실행 권한은 유지되며, 실제 인계 시에는 상단 담당자 선택란을 사용한다. 업무 화면으로 이동하는 링크는 해당 귀속월·그룹을 이어가며, 지급계획을 사용하는 환경에서는 자금 배정과 부서 협의 절차도 표시한다.

## 단계별 완료 기준

다음은 구현 인수 기준이다. 실제로 확인한 항목은 [개발 현황과 검증](status.md)에 기록한다.

| 단계 | 완료로 인정할 관찰 결과 |
|---|---|
| 1. 월 정산 접수 | 2026년 6월 최초 접수와 같은 파일 재접수에서 건수·원화 합계가 [원본 검증값](status.md)과 같다. 앱을 재시작해도 같은 건과 처리 상태가 열린다. |
| 2. 그룹 판정·소명 | D-011을 매개로 D-024·D-037이 한 그룹에 속하는 근거가 보인다. 한 키만 공유하는 별도 대리점 쌍은 직접 연결하지 않는다. 회수계좌 차이로 소명을 요청·회신·해소하고, 회신이 없으면 담당자와 다음 확인 작업이 남는다. |
| 3. 그룹 결재 | 6월 일반 건은 팀 전결, 세 대리점 합산 건은 임원 경로로 간다. 경계값 2,000,000원과 2,000,001원의 권한자가 다르다. 추가·동시 요청과 재상신에서 같은 ID가 두 번 합산되지 않는다. 권한 없는 승인이나 반려·보완 요청에서 지급지시가 생기지 않는다. |
| 4. 지급지시·대사 | 세 건을 함께 승인하면 대리점별 세 지급지시가 서로 다른 원 지급건을 가리킨다. 일부만 성공하면 성공 건만 완료된다. 금액 불일치나 미응답은 확인 작업으로 남고, 같은 회신을 다시 입력해도 완료 금액과 지시 수가 늘지 않는다. |
| 5. 승인 후 정정 | 그룹을 합치거나 나누는 정정을 입력하면 영향받은 미전송 지시가 보류되고 전후 합계·승인권자·근거가 표시된다. 필요한 재승인 후에만 다시 전송할 수 있다. 이미 전송된 건은 기존 회신을 조회하고, 기지급 건은 과거 기록과 사후 검토가 함께 남는다. |

시연에서는 일반 건 한 건을 접수부터 대사까지 처리하고, 정정으로 승인 경로가 달라지는 건과 소명 부족 또는 승인 거절로 후속 작업이 생기는 건을 확인한다. 은행 응답은 모의 입력으로 표시하며, 이후 내부 지급 상태와 회계 작업 목록은 앱이 직접 갱신한다. [참가자 문제지](../01_참가자_배포용/A01.html)
