# W07 개발 현황과 검증

## 현재 단계

월 정산 접수 → 소명 요청·회신·검토 → 그룹 결재 → 대리점별 지급지시·모의 은행 대사가 연결됐다. 상단의 시연 사용자 전환으로 영업지원 담당자, 영업지원 전결권자, 영업임원, 회계·자금의 동작을 확인할 수 있다. 기존 로컬 DB를 버전 2로 이관했고, 6월 접수 40건이 유지됐다. 검증에 사용한 결재·지급 기록은 별도의 임시 DB에만 있다.

### 로컬 실행

프로젝트 루트의 PowerShell에서 처음에는 `python -m venv .venv`와 `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`를 실행한다. 이후에는 `.\.venv\Scripts\python.exe -B app.py`로 시작해 [월 정산 접수](http://127.0.0.1:5070/)를 연다. 기본 DB는 `instance/w07.sqlite3`이며 재실행하면 같은 파일을 사용한다. 6월 그룹은 [관련자·소명](http://127.0.0.1:5070/cases?month=2026-06&group=D-011), [그룹 결재](http://127.0.0.1:5070/approvals?month=2026-06&group=D-011), [지급지시·대사](http://127.0.0.1:5070/payments?month=2026-06&group=D-011)에서 이어서 처리한다.

| 임원 승인 경로 | 6월 RB-00054(1,373,515원), RB-00120(1,189,046원), RB-00180(1,325,536원)의 합계는 **3,888,097원**이다. 현재 마스터와 전결 규정에 따른 예상 경로는 영업임원이다. 세 건 모두 원본상 미지급이다. |

### 실행 검증

- 전체 자동 테스트 15개 통과. 접수·규칙 7개, 소명·결재 4개, 지급·대사 3개, 전체 HTTP 경로·서버 재시작 1개다. 재현 명령은 `.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v`이다. 매회 임시 디스크 DB를 사용한다. [접수](../tests/test_intake.py) · [결재](../tests/test_approvals.py) · [지급·대사](../tests/test_payments.py) · [HTTP 검증](../tests/test_workflow_http.py)
- 6월 접수 전 적용 누계는 0원이고 예상액은 37,159,812원이다. 접수 후 실제 적용 누계는 예상액과 일치했다. 심사 대상 38개 그룹 중 임원 경로는 1그룹 3건이고, 팀 전결 경로는 37그룹 37건이다.
- 동시에 접수한 두 요청의 결과는 각각 신규 40건·기존 0건과 신규 0건·기존 40건이었다. HTTP 폼으로 접수 후 서버 프로세스를 종료하고 같은 DB로 재기동해 40개 정산 ID와 접수 시각이 그대로인 것을 확인했다. 재접수 결과도 신규 0건이었다.
- Chrome에서 월 전환, 대리점·정산 ID 검색, 승인 경로 필터, 페이지 이동, 직접 연결 근거와 D-024 회수계좌 차이, 접수·재접수 결과를 확인했다. 데스크톱 1440px 및 모바일 390px 너비로 점검했다.
- 경계값과 상태 조합은 원본 복사본의 추가 행으로 확인했다. 200만원은 팀 전결, 200만 1원은 임원 경로였고 반려·취소는 제외됐다. 같은 ID에 다른 금액이 오면 원금액을 보존한 채 해당 심사 건이 확인 대상으로 남았다. 잘못된 입력 행이 있으면 그 적재 회차의 새 행 전체가 롤백됐다.
- D-001의 실제 6월 988,932원은 전결권자가 승인했다. D-024에 필수 소명을 요청하자 상신이 보류됐고, 대리점 답변·증빙·해소 판단을 기록한 뒤 세 대리점 3,888,097원을 상신했다. 전결권자가 임원 역할을 폼에 임의로 기입한 요청은 서버가 HTTP 403으로 거절했다. 임원의 정상 승인 후에는 대리점별 3개 지시가 생성됐고, 모두 수취계좌 미확인으로 보류됐다.
- 금액 분리 검증에서는 이미 승인한 988,932원에 **시연용 신규 1,100,000원**을 추가했다. 월 누계 2,088,932원에 따라 임원에게 상신하고 이번 승인액인 1,100,000원에 대해서만 새 지시 하나를 생성했다. 반려·보완 요청 직후에는 지시 0건, 보완 후 재상신하면 이전 버전과 결정 사유가 보존됐다.
- 모의 회신은 금액 또는 은행·계좌가 다르면 대사 확인 중, 일치하는 실패는 지급 실패, 일치하는 성공은 대사 완료로 처리했다. 동시 전송·중복 회신에서 지시·시도·회신이 중복 생성되지 않았다. 별도 검증에서 3개 지시 중 계좌 증빙을 확인한 D-024만 대사를 완료하고 나머지 2건은 지급 보류를 유지했다.
- HTTP로 정상 건과 임원 그룹을 처리한 뒤 서버 프로세스를 종료·재기동했다. 결재 2건의 당시 근거·결정 기록, 지급지시 4건(대사 완료 1건·보류 3건), 회신 2건이 유지됐다. 소명·계좌 증빙과 은행 회신은 모두 검증용 모의 입력이다.

## 다음 작업과 미확인 항목

- 다음 지시까지 AI 연결과 승인 후 등록정보 정정·재검토는 유보한다.
- 승인 당시 마스터와 소명 증빙, 별도 임원 결재서, 실제 지급 수취계좌와 은행 처리결과는 미확인이다. 과거 결재 누락이나 실제 송금 결과의 단정은 피한다. 처리 방법은 [설계](design.md)에 있다.
- 원본 계좌는 수취계좌 증빙으로 자동 전용하지 않는다. 운영 은행이나 외부 송금 API 연결은 없으며, 시연 사용자 전환은 사내 인증을 대체하지 않는다.
