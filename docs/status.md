# W07 개발 현황과 검증

## 현재 단계

명세 작성 완료. 기존 프로젝트에는 참가자용 자료·정적 안내 페이지와 기록 설정이 있다. W07 업무 앱, 앱 DB 및 테스트는 아직 없다. 로컬 Python 3.13과 표준 SQLite 사용 가능 여부를 확인했다. Flask와 모델 API는 구현 단계에서 준비한다.

## 확인한 결과

아래 결과는 원본을 읽어 재집계한 기준값이다. 구현 후 [단계별 완료 기준](workflow.md)에 맞춰 실행한 테스트 결과를 이곳에 갱신한다.

| 확인 항목 | 원본 검증 결과 |
|---|---|
| 접수 기준값 | 대리점 50곳 중 적격 40곳. 2026년 1~6월 지급표 240건, 고유 `rebate_id` 240개. 6월은 40건 모두 미지급이고 합계는 **37,159,812원**이다. |
| 6월 그룹 판정 | D-011–D-024는 대표자·주소, D-011–D-037은 대표자·등록 정산계좌가 일치한다. D-024–D-037은 대표자만 일치하며 D-011을 통해 연결된다. |
| 임원 승인 경로 | 6월 RB-00054(1,373,515원), RB-00120(1,189,046원), RB-00180(1,325,536원)의 합계는 **3,888,097원**이다. 현재 마스터와 전결 규정에 따른 예상 경로는 영업임원이다. 세 건 모두 원본상 미지급이다. |
| 정상·예외 대조 | D-001의 6월 RB-00006은 988,932원으로 팀 전결 대상이다. 5월 RB-00005는 지급일이 6월 4일이다. 5월 RB-00083은 반려·지급일 `NONE`이다. 두 5월 건은 각각 귀속월 적용과 반려 제외를 검증하는 사례다. |
| 소명 근거 | D-024의 DP-00013·DP-00014 회수계좌는 자기 등록계좌와 다르고 D-011·D-037의 회수계좌와 같다. 원본은 지급 수취계좌나 공유 사유를 입증하지 않는다. |

근거 파일은 [대리점 마스터](../01_참가자_배포용/04_원본데이터/01_corevia/master/m_agency_cv.csv), [장려금 지급표](../01_참가자_배포용/04_원본데이터/01_corevia/sales/sales_rebate_payment_cv.csv), [회수 이력](../01_참가자_배포용/04_원본데이터/01_corevia/financials/fin_collection_history_cv.csv)이다.

명세 작성 전후 배포 자료·기록 설정·기존 루트 파일 112개의 SHA-256 비교 결과가 일치했다. 새 문서 5개의 로컬 링크도 모두 확인했다.

## 다음 작업과 미확인 항목

- 다음 작업은 월 정산 접수다. 로컬 앱과 업무 DB를 준비하고, 6월 접수·재접수·재시작에서 기준 건수와 금액 및 상태 보존을 검증한다.
- 승인 당시 마스터와 소명 증빙, 별도 임원 결재서, 실제 지급 수취계좌와 은행 처리결과는 미확인이다. 과거 결재 누락이나 실제 송금 결과의 단정은 피한다. 처리 방법은 [설계](design.md)에 있다.
- 사용할 모델 API와 접속 정보, 실제 호출 성공 여부는 미확인이다. 앱 실행·역할별 권한·상태 전이·은행 대사 테스트는 구현 이후 수행한다.
