별도 DB에서 같은 최초 결재 2건을 실행하고 **4건 모두 전송하기 전에** D-001을 정정했다. 이 경우 결재 #3의 월 누계 **4,877,029원**, 신규 승인액 **0원**, 실제 재승인액 **4,877,029원**이었다. 팀 전결 요청은 HTTP 403이었고 영업임원이 전액을 재승인했다. 네 재승인 작업은 완료됐고 최초 지급지시 #1~#4와 원금은 유지됐다. 수취계좌를 확인한 지시가 없어 네 건 모두 지급 보류였다. 각각의 전송 요청은 HTTP 400으로 차단됐다. 프로세스 재시작 후 8개 업무 테이블의 행·값, 계좌 확인 폼 4개, 전송 시도·회신 0건을 확인했다. 이때 사용한 DB는 개발 PC의 `instance/w07-e2e-all-held-20261113.sqlite3`에 보관한다.

## 중복 처리·재시작·검증 범위

- 같은 입력을 반복한 접수, AI 질문·결재안 채택, 승인, 전송, 재시도, 회신은 각각 기존 결과를 재사용했다. 소명은 1건, 그룹 결재는 3건, 지급지시는 고유 정산건 4개였다. 같은 회신 ID에 다른 처리결과를 넣거나 이미 처리한 정정 버전을 다시 제출하면 HTTP 400이었다.
- 검증 서버를 **두 번 종료·재기동**했다. 첫 번째는 임원 재승인 대기 중, 두 번째는 부분 대사 후였다. 각 시점마다 동일 DB의 16개 테이블 전체 행·값 해시가 재시작 전후 일치했다. SQLite 무결성 검사 결과는 `ok`, 외래 키 오류는 0건이었다.
- 기존 자동 회귀는 임시 DB에서 비실모델 테스트 **39개 통과**. 이 회귀 명령에서 제외한 실모델 전용 테스트는 2개다. 위 업무 흐름의 4회 호출은 검증 앱에서 직접 실행했다.
- 원본과 기존 DB는 파일 읽기만으로 시작 전후를 비교했다. 배포 원본 107개(5,359,480바이트)의 경로·크기·개별 SHA-256이 모두 일치했다. 기존 `instance/w07.sqlite3`은 양쪽 모두 212,992바이트, SHA-256 `491f15df0cec3397abfb5a370e5b5297fdbe6e8a65f8ce4b2555be1343620540`이었고 부속 파일도 없었다.
- **모의 입력과 미검증 범위**. 대리점 답변·증빙, 정정 사유, 수취계좌와 은행 회신은 시연 입력이다. 실제 대리점 회신·증빙의 진위, 회사 계정으로 한 사람의 결재, 실은행 송금·최종 처리결과는 미검증이다. D-037의 결과 미확인 상태 및 중복 전송 차단은 검증했다.
