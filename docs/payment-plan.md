# 자금 상황에 따른 판매장려금 지급계획 설계

**2026-11-14 · 설계 및 별도 DB 구현**

회계·자금이 “어느 날 누구에게 얼마를 지급해야 하며, 확인된 회사 자금으로 감당할 수 있는가?”를 판단하는 기능이다. 기존 **지급지시·대사** 화면에 지급계획을 추가한다. 자금 부족이 발생하면 AI가 대안을 작성하고, 담당자가 선택한 안을 지급계획과 부서 업무에 함께 반영한다.

## 1. 어떤 돈과 지급건을 기준으로 볼 것인가

| 구분 | 근거와 설계 결정 |
|---|---|
| 회사 자금 | Corevia 자금일보는 일자별 기초 잔액·유입·유출·기말 잔액을 제공한다. 마지막 행인 2026-06-30의 기말 잔액은 **19,080,994,674원**이다. 이 과거 합계에는 오늘의 지출 제한, 다른 지급에 배정한 돈, 개별 입금의 은행 거래번호가 없다. [자금일보](../01_참가자_배포용/04_원본데이터/01_corevia/financials/fin_cash_daily_cv.csv) |
| 지급일 | 장려금 원본의 `period_ym`은 한도 적용 귀속월이고 `payment_date`는 지급 결과다. **지급예정일**은 회계가 별도 입력한다. 처음에는 ‘예정일 미지정’에 표시하고 담당자를 지정한다. 일정을 옮겨도 귀속월·금액·승인권자는 그대로다. [장려금 지급표](../01_참가자_배포용/04_원본데이터/01_corevia/sales/sales_rebate_payment_cv.csv) |
| 계획 단위 | 사람의 승인을 거쳐 생성된 각 `instruction_id`를 한 줄로 쓴다. 그룹 결재액은 해당 줄들의 합계로 표시한다. 동일 `rebate_id`의 재승인이나 실패 재시도는 원지시에 연결한다. 계획 수립만으로 지급지시를 새로 만들지 않는다. 원장상 기지급은 과거 기록으로 조회한다. [기존 결재·지급 규칙](design.md) |
| 이번 설계의 가정 | 자금 범위는 **Corevia의 확인된 원화 지급 재원**이다. 회계·자금이 지급계획과 배정을 관리하고, 영업지원이 대리점 일정과 회수 관련 사항을 확인한다. 지시 1건을 분할 송금하지 않는다. 우선순위 기본값은 예정일, 같은 날에는 지급지시 번호 순이며 담당자가 순서를 바꾸면 사유를 남긴다. |

현재 가용액을 확인하려면 회계가 대상 계좌 범위, 잔액 기준시각, 잔액증명·거래내역의 참조번호, 사용제한액과 다른 용도 배정액을 대조해야 한다. 확인한 사람과 시각을 화면에 함께 표시한다. 잔액 근거가 없거나, 연속된 거래내역이 누락됐거나, 다른 용도 배정이 확인되지 않으면 **‘자금 확인 필요’**로 표시하고 새 배정·전송을 보류한다. 구실적을 현재 잔액으로 자동 이월하지 않는다.

## 2. 날짜별 부족액과 배정 규칙

1. **확인 잔액**은 회계가 대사한 기준 잔액에 기준시각 이후의 확인 입금을 더하고 확인 출금을 뺀 값이다. 계좌별 은행 거래 식별자로 중복을 막는다. 새 잔액을 기준으로 삼을 때 그 잔액에 들어간 거래를 다시 더하거나 빼지 않는다. 같은 회사의 대상 계좌 간 이체는 양쪽을 연결해 회사 전체의 신규 유입으로 계산하지 않는다.
2. **미배정 가용액**은 확인 잔액에서 사용제한액, 타 용도 배정액, 모든 지급일의 유효한 장려금 배정액을 뺀 값이다. 각 차감 항목은 겹치지 않게 대조한다. 조달 요청·입금 약속·미수금·AI의 예상 유입은 ‘예정’ 열에만 표시한다. 새 입금은 회계가 입금일·금액·거래 증빙을 확인한 뒤 한 번 반영한다.
3. **예정일까지의 누적 부족액**은 그날까지 미집행 지시에 *추가로 배정할 필요액*에서 현재 미배정 가용액을 뺀 양수 부분이다. 자기 지시에 이미 배정된 금액은 필요액에서 제외한다. 연체분은 첫 행으로 이월하고, 여러 날을 볼 때 같은 자유자금을 날마다 새로 주지 않는다. 날짜별 표에 당일 지급액·기배정액·미배정 필요액·그날까지의 누적 부족액을 나란히 표시한다. 미래 예상 입금은 이 계산에서 제외한다.
4. **배정은 지시 한 건의 전액 단위**다. 날짜에 금액을 적거나 AI가 대안을 보여주는 것만으로 자금이 묶이지 않는다. 회계가 ‘배정 확정’을 누르면 서버가 최신 가용액·기존 배정·승인 상태를 확인해 가능한 지시를 순서대로 배정한다. 전액을 충당하지 못한 지시는 ‘미배정’으로 두고 담당자에게 선택권을 돌린다. 배정 결과와 사유를 지시별로 반환한다. 급여·매입대금 등 다른 용도의 예약 원장에서 **같은 재원을 통제**하거나 회사가 별도로 확보한 전용 자금 범위를 사용해야 타 부서와의 중복 사용까지 막을 수 있다. 외부 배정이 바뀌는 동안 정적인 잔액 사본만으로는 이를 보장할 수 없다.
5. 잔액이 하락해 유효 배정이 재원을 초과하면 음수 차액을 **기배정 자금 부족**으로 별도 표시한다. 이때 신규 배정에 쓸 수 있는 금액은 0원이다. 이미 묶은 돈을 임의로 다른 지시에 넘기지 않고, 회계가 잔액과 미전송 지시의 배정을 대조할 때까지 추가 집행을 막는다.

## 3. AI 대안 선택부터 부서 작업까지

회계가 부족한 예정일을 선택하면 앱이 먼저 부족액, 기존 배정, 이동 가능한 미전송 지시와 보류 사유를 계산한다. AI는 이 사실과 담당자가 등록한 예상 입금·조정 가능일을 바탕으로 대안을 작성한다. 각 안에 **대상 지시, 금액, 변경 전후 날짜와 부족액, 필요한 증빙, 담당 부서·기한, 적용 조건**을 표시한다. 가능한 재원이나 조정일이 입력되지 않았다면 확인할 사항을 제안한다. 금액 계산과 권한·전송 가능 여부는 서버가 판정한다.

| 담당자가 선택한 안 | 선택 즉시 반영 | 후속 확인으로 바뀌는 사항 |
|---|---|---|
| 추가 자금 확보 | 계획에 목표액·필요일·‘입금 확인 대기’를 기록한다. 예를 들어 대금 회수라면 영업지원에 회수 일정 확인, 회계·자금에 입금 대사 작업을 연결한다. 현재 부족액을 유지한다. | 회계가 실제 거래를 연결하면 실입금액만큼 가용액을 다시 계산한다. 일부만 들어오면 잔여 조달 과제와 부족액을 유지한다. 회계가 배정을 확정하면 대상 지시에 반영된다. |
| 지급일 조정 | 미전송 지시와 후보일을 계획에 기록하고 영업지원에 대리점 일정 협의 작업을 만든다. 협의 중에는 확정 일정과 변경 예정일을 함께 표시한다. | 영업지원이 협의 결과·근거를 기록하고 회계가 확정하면 같은 지시의 예정일을 바꿔 두 날짜를 다시 계산한다. 이미 배정한 돈은 그 지시에 귀속된다. 풀어 쓰려면 회계가 미전송 여부를 확인하고 배정 해제 사유를 기록한다. 협의 불가 시 원래 날짜를 유지한다. |

기존 네 역할을 사용한다. **회계·자금**은 대안 채택·일정 확정·입금 확인·배정과 전송, **영업지원**은 회수·대리점 협의와 결과 기록, **전결권자·영업임원**은 기존 규정에 따른 장려금 승인·재승인을 담당한다. 자금 확보안을 채택하면 검토·확인 작업이 시작된다. 차입·그룹 재원 배분 등 별도 권한이 필요한 안은 해당 승인과 입금 증빙을 기다린다. AI 호출이 실패해도 계산값은 유지하고 담당자가 같은 양식으로 직접 계획을 조정할 수 있다. [기존 역할](workflow.md) · [의사결정 권한](../01_참가자_배포용/04_원본데이터/00_common/approval_authority_policy.md)

## 4. 숫자로 보는 설계 시연

6월 임원 승인 그룹의 실제 명세는 D-011 **1,373,515원**, D-024 **1,189,046원**, D-037 **1,325,536원**이다. 아래의 **7월 10일·13일, 사용 가능 자금 300만원, 추가 입금 90만원**은 설계 시연값이다. 세 지시는 모두 미전송이며 기존 배정·사용제한·기타 지출은 0원으로 가정한다. [기존 명세 검증](e2e-verification.md)

**날짜를 옮기는 안**도 같은 출발점에서 비교한다. 입금 없이 D-037 한 건을 7월 13일로 옮기기로 합의하면 7월 10일 지급액은 2,562,561원, 당일까지 부족액은 0원이다. 7월 13일에는 1,325,536원이 필요하고 자유자금은 437,439원이므로 **그날까지 888,097원이 여전히 부족하다.** 두 안은 대안 비교이며 같은 90만원을 양쪽에 반영하지 않는다. 어느 안에서도 수취계좌를 확인하지 않은 대리점에는 전송할 수 없다.

## 5. 작업 화면·저장·전송 조건

**지급지시·대사 화면에 ‘지급계획’ 보기를 추가한다.** 위쪽에는 기준시각·확인 잔액·기배정액·미배정 가용액을 표시하고, 본문은 예정일별 표와 ‘예정일 미지정’ 목록으로 구성한다. 날짜를 열면 각 지시의 대리점·귀속월·예정일·승인액·배정액·계좌 확인·은행 상태가 보인다. 담당자는 부족액 옆에서 두 대안의 날짜별 효과를 비교하고, 채택한 계획행에서 관련 부서 작업·담당자·기한·증빙·처리 상태를 확인한다.

| 저장할 기록 | 업무 연결 및 중복 방지 |
|---|---|
| 자금 근거 | 회사·계좌 범위·통화, 잔액 기준시각·증빙, 확인 입출금과 거래 고유키, 제한액·타 용도 배정 내역, 확인자·확인시각을 보존한다. |
| 지급계획·배정 이력 | 지급지시당 활성 계획행 1개, 전액 배정 최대 1개. 원 승인과 최신 재승인, 예정일, 금액, 변경 전후, 배정·잠금·소진·해제 사유를 연결한다. 모의 전송·은행 거래는 각각의 시도·거래 식별자로 추적한다. |
| AI 제안·채택·부서 작업 | 계산 기준시각, 대상 지시와 계획 버전, AI 입력 근거·원문, 담당자의 수정·선택 내용 및 시각, 부서·담당자·기한·결과 증빙을 저장한다. 같은 채택을 다시 제출하면 기존 작업과 계획 변경을 반환한다. |

채택·배정·전송 직전 서버가 최신 계획 버전과 자금·업무 상태를 다시 확인한다. 채택과 작업 생성·계획 갱신은 하나의 SQLite 쓰기 트랜잭션으로 저장한다. 배정은 가용액 재조회와 함께, 전송은 해당 배정 잠금·전송 시도 등록과 함께 원자적으로 처리한다. 동시 요청에서 뒤 요청은 갱신된 가용액으로 다시 판단한다.

| 지시의 기존 상태 | 지급계획에서 허용하는 처리 |
|---|---|
| 승인 완료·미전송 | 예정일 지정과 배정이 가능하다. 전송에는 유효 승인, 계좌·증빙 확인, 정정 보류 해제, 예정일 도래, 해당 지시 전액의 유효 배정이 모두 필요하다. |
| 정정으로 재승인·계좌 재확인 대기 | 미전송 지시의 배정을 보존하고 전송을 보류한다. 기존 절차를 완료하면 같은 지시·배정으로 다시 확인한다. |
| 이미 전송·회신 대기·금액 또는 계좌 불일치 | 배정을 잠그고 기존 시도를 대사한다. 날짜 변경, 해제·재배정, 중복 전송은 차단한다. |
| 실패 확정 | 미지급이 확인되면 기존 지시·배정으로 재시도할 수 있다. 회계가 일정을 취소·조정하며 자금을 풀 경우 이력을 남긴다. 재시도에는 유효한 전액 배정이 다시 필요하다. |
| 성공 대사 | 해당 자금 장부의 출금과 배정 소진을 함께 연결한다. 잔액에 이미 포함된 출금은 다시 차감하지 않는다. 모의 은행 성공은 시연 자금 장부에서만 정산한다. 실잔액 기준의 계획은 실제 출금이 확인될 때까지 해당 자금을 계속 잠근다. |

기존 DB 도입 시점에 미전송 승인 지시는 ‘예정일 미지정·미배정’으로 시작한다. 이미 전송된 지시는 회계가 기준 잔액에 해당 출금이 포함됐는지 대조한다. 미반영분은 잠금으로 한 번 반영하고, 대조를 끝내기 전에는 신규 배정을 열지 않는다. 완료 건은 조회 이력으로 유지한다.

## 6. 구현 인수 기준과 운영 확인사항

- 예시의 다섯 시점별 수치가 표와 일치한다. 90만원 확보안을 채택하거나 같은 입금 증빙을 두 번 입력해도 실제 입금은 한 번만 가산된다. 50만원만 입금된 경우 남은 부족액은 **388,097원**이다.
- 서로 다른 지급일·담당자가 같은 자유자금에 동시에 배정을 요청해도 가용액을 넘지 않는다. 같은 지시의 재승인·일정 변경·재시작으로 배정이나 부서 작업이 늘지 않는다.
- 같은 날 부족액과 전체 일정의 누적 부족액을 각각 대조한다. D-037 연기 시 첫 예정일의 부족액은 0원, 다음 예정일까지는 888,097원이다. 부서 협의가 끝나기 전후의 일정과 담당자 이력을 확인할 수 있다.
- 자금 전액 배정 후에도 계좌 미확인·정정 보류 지시의 직접 전송 요청을 서버가 거절한다. 미회신 지시는 잠금을 유지한다. 성공·실패·중복 회신, 출금 후 새 기준 잔액 등록에서 같은 돈이 두 번 풀리거나 차감되지 않는다.
- 가용액 확인 근거나 계획 버전이 달라진 AI 안은 금액과 날짜를 다시 비교한 뒤 채택해야 한다. 검토자가 채택한 내용과 생성된 부서 작업을 원 지급지시에서 조회할 수 있다.

## 구현 범위와 실행

기존 업무 화면 ‘지급지시·대사’에서 **지급계획**으로 이동한다. 전용 DB의 회계·자금 사용자는 일마감 기준 잔액과 증빙, 제한액·타 용도 배정액을 입력하고, 기존 승인 지시에 지급예정일을 지정한다. 날짜별 ‘배정 확정’은 그날까지의 지시를 순서대로 처리한다. 자금이 부족한 미배정 지시에서 확보 목표액과 후보일을 입력하면 AI가 두 대안을 제시한다. 검토 의견을 남겨 채택한 뒤 시연 사용자를 영업지원 또는 회계·자금으로 전환해 해당 부서 작업을 처리한다.

전용 DB는 기본 업무 DB와 별개다. 아래 명령은 독립된 새 파일을 초기화한다. 같은 명령을 다시 실행하면 그 지급계획 DB를 연다. 기존 일반 업무 DB를 이 옵션에 지정하면 시작을 거절한다. 새 DB에서는 월 접수·그룹 승인을 마치면 계획 목록에 지급지시가 나타난다.

```powershell
.\.venv\Scripts\python.exe -B app.py --funding-db .\instance\w07-funding-local.sqlite3 --port 5074
```

이번에 구현한 재원은 **단일 회사·원화 지급 전용 시연 자금**이다. 가용액은 회계가 증빙을 대조해 기록한 일마감 잔액과 마감 이후 확인 거래로 계산한다. 확보안 채택이나 회수 약속으로는 가용액이 늘지 않는다. 회계는 전용 재원 외부에서 들어온 입금만 등록하고, 재원 내부 계좌 간 이체는 증빙 대조 시 제외한다. 입금 확인은 회계의 수동 증빙 확인 절차이며 실은행 입금 조회 API와 타 부서 원장은 연결하지 않았다. 지급 대사는 기존 모의 은행을 사용한다.

이번 검증의 재현 경로와 DB별 결과는 [개발 현황과 검증](status.md#지급계획과-자금-배정)에 있다. 운영 적용을 위해 실제 지급재원 계좌·외부 배정 내역, 증빙의 유효시간, 일정 변경의 대리점 합의 조건을 확인해야 한다. 현재 배정 순서는 예정일과 지시 번호에 따라 고정된다.
